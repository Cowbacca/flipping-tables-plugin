# A future public plugin with a paid API

Investigated on 19 September 2026. Charging for a backend service appears viable, with relevant existing precedent: RuneLite's official [Plugin Hub marker for Flipping Copilot](https://github.com/runelite/plugin-hub/blob/master/plugins/flipping-copilot) points to public plugin source and declares its external GE-data uploads. The [service itself](https://flippingcopilot.com/) offers a free plan and paid upgrades. This demonstrates that a paid external service can coexist with a Hub plugin; it does not establish automatic acceptance of an entirely payment-gated service or this specific plugin.

The practical model would be a freely inspectable, open-source Java plugin calling a privately hosted subscription API. Keep billing, entitlement checks, quotas, customer isolation and proprietary modelling on the server. A check hidden in plugin code can be removed by a user and is not subscription enforcement. Use per-customer, revocable credentials rather than the current single personal server token. Website checkout/account management would be a separate implementation, outside this personal update.

RuneLite's [Plugin Hub guide](https://github.com/runelite/plugin-hub) requires a public plugin repository and review. Its [information page](https://github.com/runelite/runelite/wiki/Information-about-the-Plugin-Hub) requires disclosure for external-server communication. Declare exactly what is sent and the destination; for this integration that is cash budget, selected stock, current offers, observed limits and the network source IP. The current code asks for consent before sending a portfolio and does not include a RuneScape username, account hash, chat messages or login details in the API request. A player name is used only locally to invalidate a captured portfolio when the account changes.

Public preparation would include an explicit compatible open-source licence for the plugin (while preserving existing notices), a privacy/retention policy, per-user authentication and authorisation, server abuse limits, transparent pricing/access requirements, and review of all GE helpers against the current [rejected features](https://github.com/runelite/runelite/wiki/Rejected-or-Rolled-Back-Features) and [review process](https://github.com/runelite/runelite/wiki/Plugin-Hub-Review). In particular, keep game actions manual; do not auto-submit offers, manipulate outgoing chat, inspect other players, or add a local HTTP endpoint exposing account state.

The rejected-features page's HTTP-exposure rule should not be treated as a blanket ban on outbound GE-data APIs: the official Flipping Copilot marker explicitly permits that kind of external communication with a warning. The published policies reviewed did not provide a categorical rule for a plugin whose useful functionality is entirely paywalled. Ask RuneLite maintainers about that exact model before investing in a public launch or promising Hub availability. No maintainer has been contacted and no approval is claimed here.

The existing private API also predates multi-customer isolation: its single bearer token and globally addressable snapshots are suitable only for the current personal use. Do not sell access to that deployment until customer-specific access control is implemented and tested.
